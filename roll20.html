Roll20 import setup

Add each summon variant to your Journal once, then open its NPC sheet to roll attacks, saves, initiative, skills, and ability checks. Tokens are optional.

Requires: a campaign with Mod access and the Pathfinder by Roll20 sheet authored by Natha. This importer is for Pathfinder First Edition’s official sheet, not the Pathfinder Community or PF2E sheets.

Download companion Mod (.js)Version 1.0.1 · No other Mods required

1. Install once per campaign

  1. Open the Roll20 campaign’s details page. In Settings → Mod (API) Scripts, open the script editor.
  2. Create a New Script, name it Summoner’s Ledger, and paste the entire downloaded/copied script into the editor.
  3. Save the script. Launch the campaign and type !sledger help in chat as a GM. The Mod should whisper its help message to you.

The campaign creator needs Pro. Install only one copy of this Mod. To upgrade later, replace the code in that script and save again.

2. Import a summon

  1. In the creature library, select a creature and configure its feats, alignment template, and lighting.
  2. Click Export to Roll20 beside Copy stat block. Review the name, attack count, and import notes.
  3. Click Copy import command and paste the entire command into Roll20 chat as a GM.
  4. Open the Journal entry linked in the Mod’s response. Click attacks, saves, initiative, or skill totals on the NPC sheet to roll.

Import commands begin with !sledger import. They contain all exported statistics; the Mod does not fetch the website or need a website login.

3. Reuse the Journal entry

The importer recognizes the creature, template, and stat-affecting feat configuration. Importing the same variant again returns the existing entry without changing it. Spell level, caster level, and Superior Summoning do not create duplicates because they do not change that creature’s sheet statistics.

Starlight’s normal-light and dim-light skill totals are separate variants. Use the appropriate variant at the table; if Moonlight or Sunlight is also enabled, remember that the creature itself emits light. Daily uses, conditions, and remaining duration are tracked separately for each summoned creature.

Updating imported statistics

Enable Update the existing imported variant in the export dialog to copy an !sledger update command. This replaces fields and repeating rows owned by the importer. Manually added rows, character name, artwork, permissions, and existing tokens remain in place. Edits to an imported attack row will be replaced. An update requires that exact variant to exist first.

Default tokens are preserved during an update. If maximum HP changes, repeat the optional token setup below so newly dragged tokens start with the new maximum.

Optional: artwork and independent HP bars

No token is needed to use the sheet. To make the entry draggable as an artwork token:

  1. Place a spare artwork token on the map and select it.
  2. Click Save default token, HP bar 3 in the Mod’s import response, or run !sledger token CHARACTER_ID 3, using the character ID from that response’s Journal link.
  3. The Mod assigns the selected token to the Journal creature, fills the chosen bar with starting/max HP, unlinks all three bars, and saves it as that creature’s default token.
  4. Drag additional copies from the Journal. Each token keeps its own HP; all use the same NPC sheet for rolls.

Bar 3 is usually red; colors follow your campaign settings. Substitute 1 or 2 in the command for a different HP bar. This optional command changes the selected token, so use a spare copy. It does not change existing tokens elsewhere.

Roll and rules notes

  • Attack rows use the final totals shown in the Ledger. The sheet does not add Strength or Augment a second time.
  • A row such as 2 claws rolls both attacks; iterative weapon rows roll the listed sequence. Attack routines separated by “or” are alternatives. Choose the appropriate routine.
  • Smite is an optional effect against a qualifying target. Its bonus is not baked into every attack; its rules are imported as an ability.
  • Conditional damage and special attacks that cannot be parsed confidently remain reference text, and the export preview identifies them. Review these before play.
  • Export uses the Ledger’s current calculations. Its existing caveats for unusual ability DCs, enhancement stacking, and special attacks still apply.
Compatibility check: mapping and roll tests use Roll20’s public official-sheet source. Live campaign behavior has not been verified here. On your first import, compare one attack, a save, initiative, and Perception with the Ledger; verify the Mod response and expanded roll details.

Troubleshooting

  • No response: check that the Mod is saved/running, you are a GM, and you pasted the whole command beginning with !sledger.
  • Wrong or empty sheet: confirm the campaign uses Pathfinder by Roll20 (Natha). This Mod cannot configure the Community sheet.
  • Already imported: this is expected. Use the returned Journal link, or explicitly choose an update if the statistics need replacing.
  • Numbers differ: check the variant name and lighting. Compare attack details and calculation notes. Do not enable a second copy of Augment through a sheet buff.
  • Players cannot access the creature: new entries are GM-only. Assign “Can Be Edited & Controlled By” and Journal visibility in the character’s Edit dialog as desired.
  • Independent resource uses: the character sheet is shared. Track spent smites and similar resources with token markers or separate notes, not a shared sheet counter.
